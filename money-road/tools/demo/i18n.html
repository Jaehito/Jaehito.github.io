3. 드롭다운을 어디에 두나98 UI에는 자리가 이미 정해져 있습니다

셋 다 쓰되 역할이 다릅니다. 메뉴바는 정석이고(Windows 앱의 관용구가 그렇습니다), 첫 실행 화면의 콤보박스가 실질적으로 제일 중요합니다 — 처음 켠 사람이 메뉴를 뒤지지 않게요. 설정 대화상자는 나중에 소리·난이도와 함께 묶을 자리입니다.

  • 첫 실행은 자동 감지: navigator.language가 ko로 시작하면 한국어, 아니면 영어. 고른 값은 localStorage에 저장합니다(게임이 이미 쓰고 있습니다).
  • 메뉴 항목은 각 언어로: 목록에는 한국어와 English를 그 언어 그대로 적습니다. "Korean"이라고 쓰면 한국어를 찾는 사람이 못 읽습니다.
  • 터치 타깃 48px은 여기서도 지킵니다 — 메뉴 항목과 콤보 목록 행을 전부 48px로 잡았습니다. 98 원래 메뉴는 18px이라 그대로 쓰면 못 누릅니다.

4. 한 / 영 같은 화면A안(Galmuri11 단일)으로

한국어 UI 문자열은 영어보다 대체로 짧아서 넘칠 위험은 낮습니다. 대신 숫자 표기가 갈립니다 — 게임의 fmtWon()은 "억/만" 단위를 쓰는데, 해외판 금액 스케일($1,000 → $500M)에는 안 맞습니다. 아래는 통화까지 갈아끼운 상태입니다.

5. 구조와 작업량솔직하게

지금 index.html은 한국어 문자열이 코드 안에 직접 박혀 있습니다. 템플릿 리터럴 안에도, 배열 안에도, 조건문 안에도 있습니다. 그래서 i18n은 "드롭다운 하나 붙이기"가 아니라 문자열을 전부 걷어내는 작업입니다. 

const L = {
  ko:{ equity:'잔고', phase:'{n}단계 목표', dday:'D-{n}', sell:'매도',
       need:'하루 {p}% 필요', liq:'청산 {v}', open:'진입' },
  en:{ equity:'EQUITY', phase:'PHASE {n} TARGET', dday:'D-{n}', sell:'SELL',
       need:'NEED {p}%/DAY', liq:'LIQ {v}', open:'OPEN POSITION' }
};
let LANG = localStorage.getItem('mr_lang')
        || (navigator.language.startsWith('ko') ? 'ko' : 'en');
const t = (k, v) => (L[LANG][k]||k).replace(/\{(\w+)\}/g, (_, n) => v?.[n] ?? '');
  • 문자열 수는 대략 200~300개로 봅니다 — 화면 라벨, 모달 문구, 매도 등급 평, 댓글(REACTIONS·EVENT_LINES)까지 포함해서요. 이 중 댓글이 절반 가까이고, 번역이 아니라 다시 써야 합니다(1차 때 말씀드린 그 이유).
  • 숫자·통화 포맷이 언어마다 갈립니다. fmtWon()을 fmtMoney(v, lang)로 바꿔서 한국어는 억/만, 영어는 $1.2M 식으로 나눕니다.
  • 날짜도 갈립니다 — 게임은 3월 2일 (월)을 만듭니다. 영어는 Mar 2 (Mon)입니다. dateOfDay() 한 곳입니다.
  • 회귀 테스트가 문자열을 검사하는 곳이 있습니다(test/phase*.js). i18n을 넣으면 그 테스트들이 깨집니다 — 키로 찾도록 같이 고쳐야 합니다.
  • 서브셋 재실행: Galmuri는 쓰는 글자만 담으므로, 한국어 문자열이 바뀌면 subset-font.py를 다시 돌려야 합니다. 배포 절차에 한 줄 추가됩니다.

순서는 ① 언어 스위치와 저장 → ② 화면 라벨 → ③ 모달 → ④ 댓글 재작성 → ⑤ 포맷·날짜가 맞습니다. ①~③까지만 해도 드롭다운이 실제로 동작하는 상태가 되고, ④가 제일 오래 걸립니다.
