# 머니로드 도구

`money-road/index.html` 하나가 게임 전부다. 번들러도 빌드 단계도 없고, GitHub Pages가
그 파일을 그대로 서빙한다. 그래서 도구도 전부 이 파일 하나를 대상으로 돈다.

## 준비

```bash
cd money-road/tools
npm install            # playwright-core만 받는다
```

브라우저는 `lib/browser.js`가 `PW_CHROME` → `/opt/pw-browsers/chromium-*` →
playwright 기본 탐색 순으로 찾는다. 이미 chromium이 있으면 `playwright install` 하지 말 것.

## 바로 쓰는 것

```bash
./check.sh                      # <script> 블록 문법 검사 — 커밋 전 항상 먼저
npm test                        # 회귀 테스트 전체
node test/phase27.js            # 하나만
node sim/tier.js                # 밸런스 시뮬 (수십 초~몇 분 걸리는 것도 있다)
node shot.js /tmp/a.png "S.cash=140000;S.daysLeft=1;setBet(70000);render()"
```

`check.sh`가 제일 중요하다. 단일 HTML이라 오타 하나로 게임 전체가 죽는데,
브라우저를 열기 전까지는 아무도 안 알려준다.

## 밸런스 근거

수치를 바꾸기 전에 해당 시뮬을 먼저 돌린다. 아래는 지금 상수들이 왜 그 값인지의 기록이다.
**시뮬을 다시 돌리면 숫자가 조금씩 달라진다** — 난수 시드를 고정하지 않았고, 결론이
바뀌지 않을 만큼의 표본(각 500~800회)만 돌리기 때문이다.

| 시뮬 | 무엇을 증명했나 |
|---|---|
| `sim/gate.js` | **관문(상환 기한)이 유일하게 먹힌 난이도 장치.** 패턴을 하나도 안 건드리고 클리어 99% → 22%. 성공 런 22분 / 실패 런 9분으로 길이도 균형이 잡힌다. `GATES` 일수표의 출처. |
| `sim/stake.js` | **베팅 규칙으로는 난이도를 못 만든다.** 자산 70%를 매 판 강제로 걸게 해도 클리어 88%. 판당 기댓값이 복리를 못 이긴다. |
| `sim/ev.js` | 판당 기댓값 = 1배에서 1.23, **3배에서 1.68**. 위 두 결론의 뿌리. `PACE_OK`/`PACE_WARN` 임계값도 여기서 나왔다. |
| `sim/carry.js` | **폐기된 장치의 기록.** 이월 상한 0 → 무제한에서 클리어 22% → 41%. 거래일은 복리로 붙기 때문에(5일 ≈ 13배) 상한을 몇 일로 잡든 "관문을 넘으면 갑자기 편해지는" 구간이 남는다. 이월 자체를 삭제했다. |
| `sim/news.js` | **장중 뉴스 적중률의 근거.** "하락 뉴스면 즉시 매도" 전략으로 재면 뉴스 없음 21% · 50% 20% · 60% 22% · **70% 27%** · 85% 30% · 100% 41%. 60% 이하는 동전던지기라 죽은 기능이 되고, 100%면 매도 타이밍 게임이 통째로 무너진다. → `NEWS_ACC=0.70`. |
| `sim/water.js` | **물타기에 수수료를 안 붙인 근거.** 기계적으로 쓰면(평단 −10%에서 50% 추가) 클리어 17% → 12%, 파산 11% → 14%. 지는 판에만 더 걸고 이기는 판엔 안 거는 역-켈리라 판당 기댓값이 양수여도 성장률이 깎인다. 물탈 몫을 미리 빼두고 베팅하면 2%까지 떨어진다. 수수료 5%를 얹으면 8% — 아무도 안 쓰는 죽은 버튼이 된다. → `WATER_FRAC=0.5`, 수수료 없음. |
| `sim/tier.js` | **난이도 사다리.** 최소 레버리지는 축으로 못 쓴다 — 1배 클리어 10%(관문실패 90%·파산 0%) / 2배 23% / 3배 35% / 5배 41%로 **낮출수록 어려워진다**(파산은 사라지지만 복리가 느려 관문을 못 채운다). 즉 레버리지는 난이도가 아니라 속도 다이얼이다. 남은 두 축만 쓴다: 하락 가중 +0/2/4/6/8/12%p → 33/28/19/13/7/1%, 관문 일수 +2/0/−2/−4 → 27/21/11/7%. 확정 사다리 37% → 27% → 17% → 13% → 7%이고, **3단계가 지금까지의 난이도**다. → `TIERS`. |
| `sim/bonus.js` | 이월을 **조기 상환 현금 보너스**로 대체. 그냥 삭제하면 클리어 18% → 9%로 너무 가혹하다. `보너스 10%/일 + 관문 일수 +1`이면 19%로 현행과 같아진다. 보너스 일수 상한은 두지 않았다 — 상한 5일을 걸면 15%로 오히려 더 어려워져서 조율할 상수만 하나 더 는다. → `EARLY_BONUS_RATE=0.10`, `GATES` 일수 전부 +1. |
| `sim/interest.js` | **기각된 대안.** 이자 12%는 클리어 62%지만 성공 런 77분 / 실패 런 33분으로 너무 늘어진다. 관문이 이겼다. |
| `sim/crash.js` | **기각된 대안.** 폭락 이벤트로는 파산률이 안 오른다. 손절이 항상 먹혀서 한 판 손실에 상한이 잡힌다. 큰 손실을 만들 수 있는 건 청산뿐. |
| `sim/signal.js`, `sim/signal2.js` | 신호의 값어치는 수익이 아니라 **사고 감소**. 5배에서 전액 손실률 신호없음 43% → 기본 15% → 정보력 최대 4.6%. |
| `sim/info.js` | 정보력 55%→85%는 도달률을 97%→98%로 거의 안 바꾸고 **속도만** 41판→29판으로 줄인다. 값이 속도값에 비해 너무 쌌다 → 상한 78%, 가격 상향. |
| `sim/debt.js`, `sim/ruin.js` | 3배 초보 파산률 76% → 2배 17% → 1배 0%. 같은 3배라도 손절을 배우면 76%→2%. **최소 레버리지가 가장 센 난이도 다이얼**이라는 근거. 예전에는 레거시 "빚 청산"으로 내렸지만(반복 플레이의 보상이 곧 난이도 완화라 삭제), 지금은 `MIN_LEVERAGE=3` 고정이고 이 축은 난이도 선택으로 옮겨간다. |
| `sim/grade.js`, `sim/grade2.js` | 매도 등급을 "고점 대비"로 잡으면 하락장에서 **전원 D**가 나온다(매도 시점이 곧 그 순간의 최저점이라). 최저~최고 범위로 바꿔야 상승·하락장 구분 없이 실력순으로 갈린다. |
| `sim/run.js` | 전체 런 통계 — 위 변경들의 종합 확인. |

### 종목이 "성격"을 갖는 구조

신호는 **등급**(강세/보통/약세)까지만 말하고, 그 등급 안에서 어떤 패턴이 나올지는
종목의 `patW`(패턴별 가중치 배수)가 정한다. 이 분리가 중요하다:

- 등급 분포는 종목과 무관하다 → **종목을 바꿔도 신호가 유효**하므로 다시 뽑을 필요가 없고,
  "좋은 신호가 뜰 때까지 종목 돌리기"가 닫힌다.
- 그래도 종목마다 다른 판이 나온다 → 진폭(`pMult`)만 다르면 종목은 변동성 사다리일 뿐이다.

원래 ETF는 "신호가 항상 맞는 종목"으로 잡았다가 접었다. 신호가 종목과 무관하게 한 번만
뽑히므로, ETF에서 참값을 보고 진폭 큰 종목으로 갈아타면 그만이라 **ETF가 다른 종목의
치트키**가 된다. 종목을 바꿀 때 신호를 다시 뽑으면 막히지만, 그러면 신호 돌리기가 열린다.

`sim/_harness.js`(원래 `sim_progress.js`)가 공용 패턴 생성기다. 다른 시뮬이 이 파일의
앞부분을 `eval`해서 쓴다 — **게임의 `PATTERNS`/`buildMultiPhase`를 손으로 옮겨 적은
사본**이라, 게임 쪽 패턴을 고치면 여기도 같이 고쳐야 결과가 유효하다.

라운드 길이는 이제 종목별 속성이다(`ticks`, 코인만 400틱=20초). 시뮬은 전부 기본
300틱 기준이라 사본을 고칠 필요가 없다 — **패턴 모양은 틱 수와 무관**하고, 노이즈는
`noiseScale(T)=√(30/T)`가 보정해서 틱이 늘어도 흔들림의 크기가 같다(phase27 2번).

## 회귀 테스트

`test/phaseNN.js`는 그 단계에서 바꾼 것만 확인한다. 전 기능 커버리지가 아니다.

- `phase15` — 티켓(연승 보상), 매도 등급, 레거시, 단타 카드 머리의 상환금·D-day 칩
- `phase16` — 상환 기한 도입, 배당주 삭제, 사건 기반 댓글
- `phase17` — 기한 연출/UI (필요 수익률, 경고 3단계, 첫 진입 안내, 장 마감 줄)
  · D-day가 스트립에서 탑바 칩으로 옮겨가 2번 항목이 `#repayChip`을 본다
- `phase18` — 장 마감 줄 축소(한 줄), 완제하면 바로 정산, 이월 삭제 → 조기 상환 보너스
- `phase19` — 레거시 구매 트리 삭제 → 트레이더 경험치(메타 레벨), 자동 익절이 메타 해금으로 이동
- `phase20` — 난이도 선택(승천): 사다리 값, 가중치 재계산 누적 방지, 완제로만 해금, XP 배율
- `phase21` — 공매도: 손익 부호 대칭, 방향별 청산선, 매도 등급 반전, 경고 영역 경계, 방향 토글
- `phase22` — 분할 매도: 금액 분할, 판당 1회, 결과 합산, 가중평균 등급, 티켓 효과가 안 불어나는지
- `phase23` — 물타기: 평단 계산, 청산선 이동, 손실 중일 때만, 손익·자동 익절이 평단 기준, 분할 매도와 조합
- `phase25` — ETF·동전주와 종목 성격: pending이 등급 구조인지, 종목을 바꿔도 신호가 그대로인지, 등급 안 패턴 분포
- `phase26` — 패턴 도감: 판당 1회 적립, 화면 비율이 실제 분포와 맞는지, 종목별로 달라지는지, 신호 적중률 불변
- `phase27` — 코인과 종목별 라운드 길이: 틱 수, 노이즈 보정, 진행바·남은 시간, y축 하한

자동 익절과 장중 뉴스를 삭제하면서 `phase24`(뉴스)는 통째로 지웠고 `phase15`·`phase21`·
`phase27`에서 해당 검사를 뺐다. **기능을 의도적으로 없앤 뒤 옛 테스트가 깨지는 건
회귀가 아니다 — 그때는 테스트를 고친다.**

  **라운드가 화면에 들어가는가**(390×844·360×640에서 넘침과 매도 버튼 여유를 잰다 —
  `scrollHeight`는 `clientHeight` 아래로 안 내려가서 거짓말을 하므로 보이는 자식을 직접 더한다)
- `phase29` — 패턴 분포 개편: 전반부 저점이 등급을 숨기는가, 급락 바닥이 청산선 위인가,
  약세 판의 탈출 창, 끝값 분리, 급등급락의 등급 이동, 단조 비중, 도감 스파크라인 방향
- `phase30` — 테스트 도구: 여는 조건(한 번·느린 두 번으로는 안 열림), 다섯 탭,
  패턴 강제·가중치·그림 설명 위치, 메타 공식과 해금 문턱, 파산 수치(파산선·청산 여유·연장),
  시작/밸런스 손잡이, **탭별 ↺가 그 탭만 되돌리는가**, ▶ 재시작,
  템플릿 JSON 왕복과 슬롯, 라운드 중 차단, 초기화가 진짜 지우는가
- `phase32` — 98 전환과 그 뒤: 서체가 실제로 로드됐는가(CDN 없이),
  화면에 이모지가 한 자도 안 남았는가, 아이콘이 SVG로 그려지는가(태그가 글자로
  새면 안 된다), 글자 크기가 11의 배수인가, 대화상자가 뜨면 부모 제목표가
  회색이 되는가, 메뉴바 언어 전환, 진행바가 칸으로 끊어 차는가, 390px에서 안 잘리는가,
  **터미널 패널 — 숫자는 도트인가, 한글 문장이 도트로 새지 않았는가, 배율이 남색이 아닌가**
- `phase31` — 언어(한국어/영어): 한국어 기본값이 예전 그대로인가, 첫 실행 감지,
  저장·복원, 전환이 화면을 다시 그리는가, 폴백(키 이름이 화면에 새면 안 된다),
  `devWipe('all')`이 언어를 안 지우는가, 🛠 도구의 언어 버튼,
  돈 표기 한/영 대조, 날짜 표기, 댓글 목록이 실제로 갈렸는가(+ 심의 표현),
  **모달 열 개 + 화면 본체를 영어로 열어 한글이 남은 곳 찾기**

**기능을 의도적으로 없앤 뒤 옛 테스트가 깨지는 건 회귀가 아니다.** 그때는 테스트를 고친다.
테스트가 레벨업/결과 모달에 막혀 멈추는 경우가 많으니, 라운드를 여러 번 돌릴 때는
`S.level=8; S.peakCash=6e10`을 박아두고 라운드 사이에 `$('mOk').click()`을 넣는다.

## 배포

```bash
# 한국어/영어 문자열을 고쳤으면 서브셋 폰트를 다시 박는다
python3 tools/subset-font.py index.html \
  <Galmuri11.woff2> <Galmuri11-Bold.woff2>

./check.sh && npm test                  # 통과해야 함
git commit && git push -u origin <branch>
git checkout master && git merge --ff-only <branch> && git push origin master
```

Pages는 `master`를 직접 서빙한다(빌드 액션 없음). 자동 커밋도 없다 — 전부 수동이다.

**서브셋 폰트를 잊어도 `check.sh`가 잡는다.** 픽셀 서체는 CDN이 아니라 파일에 박혀
있고 쓰는 글자만 남겨 두기 때문에, 새 글자를 넣고 서브셋을 안 돌리면 그 글자만
시스템 고딕으로 떨어진다 — 오류는 안 나고 화면만 조용히 망가진다. `check.sh`가
`<body>` 아래 문자열 리터럴의 모든 글자가 서브셋 안에 있는지 확인한다.
(이모지는 뺀다. 한글 서체에 애초에 없고, 게임 화면에는 한 자도 안 남았다 — phase32가 본다.)

### Claude Artifact 미러

```bash
python3 build-artifact.py /tmp/artifact.html
```

`<!doctype>/<html>/<head>/<body>`를 빼고 `<title>+<style>+본문`만 남긴다(Artifact가
그 골격을 자기가 감싸므로). Artifact CSP는 fonts.googleapis.com 외 스타일시트를 막아서
Pretendard(jsdelivr) 링크도 같이 제거된다 — **Pages판과 Artifact판의 본문 폰트가 다른 건
버그가 아니라 이것 때문이다.**

기존 아티팩트를 갱신할 때는 반드시 먼저 읽고(`action:"read"`) 그 위에 얹는다.

Google Fonts의 픽셀 폰트에는 **한글 글리프가 없다.** 그래서 한글 픽셀 폰트는 파일에
직접 박는 수밖에 없는데, 서브셋하면 부담이 없다: 원본 505KB → 실제 쓰는 301자만 8KB
(Bold 포함 15KB). jsDelivr는 이 환경 네트워크 정책에서 막히므로 npm 레지스트리에서 받는다.
Galmuri는 OFL-1.1이라 임베딩이 허용되며, **저작권 표기를 남겨야 한다.**

## sim/ — 게임 원본을 쓰는 쪽으로

`sim/_game.js`가 `index.html`에서 **진짜 경로 생성기를 잘라온다**
(`randn` · `noiseScale`/`dev`/`buildMultiPhase`/`buildFlat` · `PATTERNS` · `PATTERN_TIER`).
종목 진폭이 들어가는 시뮬은 **반드시 이걸 쓸 것.**

`_harness.js`는 PATTERNS를 손으로 베낀 사본이라 게임이 바뀌면 조용히 어긋난다.
실제로 한 번 크게 당했다 — 종목 진폭을 흉내낸다고 완성된 경로를 `1+(v-1)*amp`로
늘렸는데, 그러면 `dev()`의 0.05 하한을 건너뛰어 **가격이 음수가 된다**(진폭 2.6배에서
1초 하락률 −162%로 발견). 시뮬 네 개를 다시 돌려야 했다. 진폭은 언제나 생성기 안에서
`pMult`로 적용한다.

- `sim/spread.js` — 등급 간 간격과 초반 흔들기. 전략 넷(트레일링·쫄보·보유·신호)을
  같이 돌려 **무엇이 정답이 되는지**를 본다. 쫄보 70%→9%가 여기서 나온다.
- `sim/deadends.js` — 죽은 가설 셋(종목별 증거금·베팅상한·체결지연)의 기록.
  전부 진폭 우위를 못 뒤집는다.
- `sim/xp.js` — 메타 해금 속도. 900 XP가 6~8판이고 사다리가 뒤집혀 있다.
- `sim/crash1st.js` — 상승장에도 전반부 급락을 깔았을 때. 전반부 은폐는 되지만
  버틸 근거가 같이 사라져 모든 전략이 무너진다. 왜 탈출 창이 필요한지의 근거.
- `sim/bounce.js` — 급락 뒤 탈출 창과 **급락 깊이 스윕**. 채택값 0.84가 여기서 나온다.
  깊이가 이 개편의 유일한 조정 손잡이다 — 올리면(0.86~0.88) 트레일링이 다시 살아난다.

### 문장 규칙 두 개

1. **`재신청은 언제든 가능합니다`는 절대 바꾸지 않는다.** 계좌 회수와 정산에 같은 문장이
   반복되고, 그게 이 게임의 주제문이다 — 처음엔 친절로, 열 번째엔 다르게 읽힌다.
   반복되는 실패가 서사를 갉아먹는 대신 **서사를 완성하는** 유일한 장치다.
2. **회수 화면에 "당신 잘못"이라는 말을 넣지 않는다.** 회사는 화내지 않는다.
   사무적일수록 무섭고, 그게 안 1의 톤이다.

### 한국어 조판 규칙 (실제로 당했다)

**숫자 뒤에 조사를 바로 붙이지 않는다.** 픽셀 폰트에서 `$200,000이`는 `$200,0000`으로 읽힌다.
숫자 뒤는 **마침표로 끊거나 공백+단어**로 잇는다. `이`·`의`처럼 자릿수로 보이는 조사가 특히 위험하다.
한국어 문자열 전체에 적용할 규칙이다.

`demo/i18n.html` — **한국어/영어 전환.** 드롭다운보다 **서체가 먼저 걸린다** —
확정한 Jersey 10에는 한글 글리프가 없어서 한국어를 켜면 전부 두부(□)가 된다.

**결론: Galmuri11 단일.** 한 서체로 두 언어를 다 쓴다. 이유는 미감이 아니라 **검증 비용**이다 —
언어 전환은 런타임에 일어나므로 서체가 바뀌면 모든 화면을 두 번 확인해야 한다. 한 서체면 한 번이다.
Galmuri는 라틴 글리프도 갖고 있고 픽셀 게임용으로 만들어진 서체라 98 베벨과도 잘 붙는다.
`subset-font.py`로 496KB → **11.4KB(Regular) + 10KB(Bold), 글리프 445자**.

| 안 | 판정 | 이유 |
|---|---|---|
| Galmuri11 단일 | **채택** | 자간·행간·버튼 높이가 언어 전환에 안 흔들린다 |
| Jersey 10 + Galmuri11 전환 | 주의 | 영어 모양은 지키지만 **언어마다 레이아웃을 따로 검증**해야 한다 |
| DotGothic16 단일 | 비추천 | 자간이 넓어 한 줄에 제일 적게 들어가고 픽셀감도 약하다 |

**드롭다운은 세 자리를 다 쓰되 역할이 다르다** — 메뉴바 `보기 ▸ 언어`가 정석,
**첫 실행 화면의 콤보박스**가 실질적으로 제일 중요하고(처음 켠 사람이 메뉴를 안 뒤지게),
설정 대화상자는 나중에 소리·난이도와 묶을 자리다. 항목은 각 언어 그대로 적는다
(`한국어` / `English` — "Korean"이라 쓰면 한국어를 찾는 사람이 못 읽는다).
98 원래 메뉴는 18px이라 **전부 48px로 키웠다.**

### i18n — 다 끝난 뒤의 구조 (①~⑤ 완료)

순서는 ① 언어 스위치·저장 → ② 화면 라벨 → ③ 모달 → ④ 댓글 재작성 → ⑤ 포맷·날짜로
갔고, 다섯 단계 전부 `master`에 올라가 있다. 남은 건 드롭다운을 🛠 도구 밖으로 꺼내는
일뿐인데, 그건 윈도우 98 메뉴바가 생길 때 같이 한다.

**문자열은 `L={ko,en}` 한 군데에, 읽는 건 `t(key, vars)` 하나로.**
`t()`는 영어에 키가 없으면 한국어로 떨어진다 — 사전에도 없으면 키 이름을 그대로
돌려주지만, 그건 개발 중에만 보이게 하려는 것이고 화면에 새면 안 된다(phase31이 본다).

**데이터 표는 게터로 바꿨다.** `TRADE_STOCKS`·`GATES`·`TIERS`·`META_UNLOCKS`·`LEVELS`·
`PATTERNS`·`SIGNAL_INFO`·`BUFFS`가 전부 이 꼴이다.

```js
{id:'up', emo:'📈', get name(){return t('patUp');}}
```

읽는 쪽(`st.name`)을 한 줄도 안 고치고 언어에 반응하게 만드는 방법이다.
`JSON.stringify`도 그대로 돌아서 테스트가 안 깨진다. 리팩터링으로 풀려고 하면
호출부 수십 곳을 건드려야 한다 — 게터가 훨씬 싸다.

**댓글만은 사전에 넣지 않았다.** `CHAT={ko,en}`에 이름·반응·사건 문장을 목록째로
갈라 뒀다. 문장 하나가 아니라 목록이고, 영어판이 번역이 아니기 때문이다 —
"ㅋㅋ·ㄷㄷ·존댓말"을 영어로 옮기면 전부 어색해지고, 반대로 "exit liquidity"를
한국어로 옮길 방법이 없다. `EVENT_LINES`에는 `when` 조건만 남겼다(조건은 언어와
무관하다). 문장은 `evLines(id, R)`이 `CHAT`에서 꺼내고, 영어에 빠진 사건이 있으면
한국어로 떨어진다.

**돈은 내부 숫자 하나에 표기만 둘이다.** 원 단위 정수 그대로 두고 `fmtMoney()`가
언어를 보고 갈라진다. 영어는 100으로 나눠 달러로 쓴다 — 환율이 아니라, 밸런스를
한 줄도 안 건드리고 영어권 눈에 자연스러운 자릿수로 떨어지는 값이라 골랐다
(시드 $1,000 · 1차 목표 $5,000 · 최종 목표 $500M). 시드·최소 베팅·게이트 일곱 개가
전부 100으로 나누어져서 잔돈이 안 생긴다. 세이브도 언어와 무관하게 호환된다.

두 언어 다 아래 자리를 버린다(`50만원` · `$12.3K`). 한국어판이 처음부터 그렇게 썼고
이유도 같다 — 지금 얼마인지가 아니라 목표에 얼마나 가까운지가 중요하다.

#### 실제로 당한 것 넷

1. **`t`라는 이름을 가리는 자리가 널려 있다.** `TIERS.map((t,i)=>...)`, 
   `out.map(t=>({text:t}))` — 원래 `t`를 임시 변수로 쓰던 관례가 있었다. 번역 함수를
   `t`로 만든 순간 이 자리들이 전부 지뢰가 된다. 조용히 실패하지 않고 "t is not a
   function"으로 죽어주는 게 그나마 다행이다. 새 코드에서 `t`를 변수 이름으로 쓰지 말 것.

2. **회귀 테스트가 컨테이너 로케일을 따라가고 있었다.** 게임이 `navigator.language`로
   첫 언어를 정하는데 이 컨테이너는 `en-US`라서, 15~30단계 로그가 **조용히 영어로**
   바뀌어 있었다. 테스트는 전부 통과했다 — 대부분 값을 찍어보는 로그라서. 예전 출력과
   비교가 안 되면 회귀 로그는 쓸모없다. `lib/browser.js`의 `newPage`가 `locale:'ko-KR'`을
   기본으로 밀어 넣게 고쳤다. 언어를 보는 테스트만 `locale`을 직접 넘겨 덮는다.

3. **영어에 한글이 남았는지는 눈으로 못 찾는다.** 모달 열 개를 한 번씩 열어보며
   훑으면 꼭 한둘을 놓친다. phase31 11번이 영어로 두고 모달을 하나씩 열어
   `[가-힣]`을 찾는다. 만들고 나서 일부러 `ko`로 돌려 탐지가 실제로 잡는지 확인했다
   (열 개 전부 검출). **검사를 추가하면 검사가 실패하는 것도 한 번 봐야 한다.**

4. **심의 표현은 지운 뒤에도 다시 샌다.** `한강뷰거주`·`한강은 참으세요 진짜`를
   ④에서 걷어냈는데, 댓글은 문장을 계속 더하는 자리라 한 번 지웠다고 끝이 아니다.
   phase31 10번이 `CHAT` 전체에서 `한강`을 찾는다.

#### 남은 것

- **한국어 문자열이 바뀌면 `subset-font.py`를 다시 돌려야 한다** — 98 전환 때
  배포 절차에 한 줄 는다. 지금은 웹폰트(Pretendard)라 해당 없음.
- 서빙되는 HTML의 `<meta name="description">`은 한국어 그대로다. 크롤러는
  자바스크립트 전의 문서를 읽으니 JS에서 바꿔봐야 소용없다 — 어느 언어를 기본으로
  서빙할지는 출시 때 정할 일이다.
- 🛠 테스트 도구 안의 문자열(52개)은 일부러 한국어다. 개발용이라 번역할 이유가 없고,
  phase31의 전수 검사에서도 뺐다.

### 윈도우 98 전환 — 실제로 옮기고 나서

목업은 `demo/win98.html`, 옮긴 결과가 지금 `index.html`이다. 옮기며 정한 것과
당한 것을 남긴다.

**토큰 이름은 그대로 두고 값만 98로 옮겼다.** `var(--blue)` 같은 참조가 200곳이
넘어서 이름을 바꾸면 그게 곧 전면 수정이다. `--blue:#3182F6` → `#000080`,
`--card:#fff` → `#c0c0c0`, `--radius:0`, `--shadow:none`. 여기에 베벨 네 색
(`--hi --lt --sh --dk`)을 더한 것이 98 입체의 전부다 — 돌출과 침강 둘뿐이다.

**글자 크기는 11의 배수만 쓴다.** Galmuri11이 11px 격자로 그려져서 배수가 아니면
글자가 뭉갠다. 쓸 수 있는 크기는 11 · 22 · 33 · 44 넷뿐이고, phase32가 화면 전체를
훑어서 어긋난 크기를 잡는다. 제약이지만 덕분에 크기 체계가 넷으로 정리됐다.

**세로가 길어질 줄 알았는데 5%였다.** 본문이 15px → 22px인데 804px → 847px.
98의 창 부품이 얇고, 그룹박스가 둥근 카드보다 촘촘하게 붙어서 커진 글자를
그만큼 흡수한다. 재 보기 전에는 1.3배로 잡고 있었다.

**이모지 40여 곳을 직접 그린 16×16 아이콘 26개로 바꿨다.** `ic(name, scale)`이
비트맵 문자열을 rect로 그린다. 데이터 표의 `emo`는 게터로 바꿔서
(`get emo(){return ic('stable');}`) 읽는 쪽을 한 줄도 안 고쳤다 — i18n 때 쓴 것과
같은 수법이다. 종목 여섯은 그림이 아니라 그 종목의 미니 차트다.

#### 실제로 당한 것 넷

1. **SVG 문자열을 `textContent`에 넣으면 태그가 글자로 찍힌다.** 라운드 화면 머리에
   `<svg class="ic" width="32"...`가 그대로 떴다. 오류가 안 나서 화면을 안 보면 모른다.
   phase32가 `#app` 전체 텍스트에서 `<svg`를 찾는다.

2. **아이콘 이름이 겹쳤다.** 동전 그림 `coin`과 종목 `coin`(코인)이 같은 이름이라,
   `ic('coin')`이 종목 스파크라인 대신 동전을 내줬다. 종목 id가 곧 아이콘 이름이라
   겹치는 쪽을 `money`로 옮겼다. **id를 아이콘 이름으로 쓰면 이름 공간이 하나가 된다.**

3. **`✓`(U+2713)가 Galmuri11에 없다.** 두면 그 글자만 시스템 고딕으로 떨어져서
   픽셀 화면에 안티앨리어싱된 체크가 하나 뜬다. 초록색과 낱말이 이미 같은 말을
   하고 있어서 그냥 지웠다. `·×→−∨∧●□↺⚠`는 있다.

4. **웹폰트가 조용히 떨어지면 아무 일도 안 일어난다.** 그래서 `check.sh`에 폰트
   검사를 넣었다(위 배포 절 참고). 검사를 넣은 뒤 일부러 없는 글자를 넣어
   잡히는 것도 확인했다.

#### 모달 열 곳을 안 고치고 98 창 모양을 얻은 방법

대화상자에 제목표를 달아야 하는데 모달이 열 곳이 넘는다. `#modal`에
`MutationObserver`를 하나 걸고, `.on`이 붙는 순간 본문의 `.emo` 아이콘을 16px로
줄여 제목표에 올린다. 같은 관찰자가 부모 창 제목표에 `.off`를 걸어 회색으로 죽인다
— 98이 초점을 옮기는 방식이고, 98을 써 본 사람이 가장 먼저 알아보는 자리다.
제목표의 글자는 프로그램 이름을 쓴다. 본문의 `.tt`가 이미 그 판의 문장을 크게
말하고 있어서, 제목표에 같은 문장을 또 올리면 한 화면에서 같은 말을 두 번 읽힌다.

### 터미널 패널과 소품 아이콘 (98 다음에 온 것)

98로 옮기고 나서 "감성은 좋은데 게임 같지 않다 / 도트는 안 읽힌다"는 지적을
받았다. 둘 다 틀린 게 아니라 **엉뚱한 곳에 쓴 것**이었다.

**98 크롬은 원래 물러나라고 만든 언어다.** 1998년의 설계 목표가 그거였다 —
창틀이 내용과 경쟁하면 안 되니까. 그래서 게임 전체를 OS 크롬으로 만들면
안 보이려고 설계된 디자인으로 게임을 만든 셈이 된다. 주사선을 얹어도
성질상 안 고쳐진다. 그리고 정작 이 게임의 전부인 차트가 흰 바탕에 얇은 선
하나였다 — **창틀보다 덜 꾸며져 있었다.**

**도트는 한글 문장에서 무너진 것이지 숫자에서 무너진 게 아니다.**
"흘러내리기"는 11×11 상자에 안 들어가지만 `1.62x` `D-13` `+13%`는 잘 들어간다.
서체를 통째로 갈아엎은 건 과잉 대응이었다.

그래서 도트를 숫자가 사는 곳으로 되돌리고 그 자리를 어둡게 팠다(`.trm`).
1998년 금융 단말기가 실제로 그랬다 — 사무용 PC 안에 뜬 트레이딩 터미널이다.
회색 창은 그대로고 **숫자 블록만 검다**: 계좌(목표·잔고·게이지)와 라운드
화면(배율·차트·손익·남은 시간). 주사선과 비네팅도 이 패널에만 건다.

**규칙 하나가 이 설계의 전부다 — 터미널 안이라도 한글이 들어가는 줄은
아웃라인이다.** 도트가 무너지는 건 낱말이 아니라 문장이고, "사성전자"를
11px 격자에 넣으면 고쳤던 문제가 그대로 돌아온다. phase32 9번이 이걸 본다.

#### 두 서체가 한 화면에 있을 때

크기 체계도 둘이다. 회색 창은 아웃라인이라 **12 / 12.5 / 15 / 17 / 19 / 26 / 40**,
터미널 안은 도트라 **11의 배수**. phase32 4번이 `.trm` 안팎을 갈라서 검사한다.

`.trm`에 `font-size:11px`을 반드시 준다. 안 주면 크기를 안 정한 자식이
body의 15px을 물려받아 격자 밖에서 도트로 그려진다 — 오류는 안 나고
글자만 뭉갠다. 처음에 이걸로 네 곳이 어긋났고, 검사가 잡아서 알았다.

**검은 화면에서 남색(`#000080`)은 그냥 안 보인다.** `.round-mult.down`이
`.trm .down`보다 아래에 있어서 같은 특정도로 이겼고, 배율이 검은 바탕에
남색으로 떠서 안 보였다. 터미널 안쪽은 이름을 다 붙여 덮어야 한다
(`.trm .round-mult.down`). 인광 팔레트는 수익 `#ff5a5a`, 손실 `#42d9ff`,
바탕 `#33ff77`, 경고 `#ffb000` — 파랑을 청록으로 올린 건 검은 화면에서
잠기기 때문이다.

#### 아이콘 — 표지판에서 소품으로

자물쇠=잠김, 돋보기=정보, 방패=보호, 트로피=성취. 이건 아이콘이 아니라
**표지판**이다. OS와 길안내의 언어라서 어떤 게임에 갖다 놔도 말이 되고,
**그 말 된다는 점이 곧 무개성**이다. "AI가 그린 것 같다"의 정체가 이거였다.

진짜 게임 아이콘은 대개 **그 세계에 실제로 있는 물건**이다. 그래서 1998년
사무실의 소품으로 갈았다 — 도장(해금) 전화기(정보력·인맥) 전표(손절 보험)
봉투(완제·현금) 바인더(패턴 도감) 사원증(경험치) 플로피 티켓(연승 보상).

게임이 이미 자기 물건 이름을 대고 있었다 — 연승 보상 셋을 코드가 `티켓`이라
부른다(`stNextTicket`). **이름은 물건인데 그림만 표지판이었다.** 셋을 같은
티켓 모양에 안쪽 표시만 다르게 그리니 "한 종류"가 그림으로 읽힌다.
레벨 7 보상 이름이 실제로 "인맥"이라 전화기가 맞고, 트로피를 주는 회사는
없지만 봉투를 주는 회사는 있다.

**그리는 법도 바꿨다.** 가는 선은 16×16에서 획이 흩어진다. 레트로 아이템의
문법은 **꽉 찬 실루엣에 1px 검은 외곽선**이고, 같은 격자인데 덩어리로 보이니
작아도 읽힌다.

**탭에는 아이콘을 안 붙인다.** 98의 탭 컨트롤에 원래 없었고, 길안내는 소품으로
그릴 수 있는 자리가 아니다 — 억지로 붙이면 다시 표지판이 된다.
종목 여섯(미니 차트)과 장세 화살표는 그대로 둔다. 종목은 처음부터 표지판이
아니었고, 방향은 물건으로 못 그린다.

### 시초 눌림을 얕게 — 남아 있던 "정답" 하나를 없앤 작업

플레이어의 지적 둘로 시작했다. ② 하락 판에도 초반에 오르는 구간이 있어서 거기서
팔면 된다. ③ 급락 뒤에 늘 반등이 와서 파산을 할 수가 없다.

**둘 다 맞았고, 원인은 하나였다 — `DIP`다.**

`sim/warmtrail.js`가 잰 것: 시초 25~35%는 아무것도 하지 않고 버티다가 그 뒤로
트레일링만 하는 봇이 **클리어 36~43%**, 나머지 전략은 전부 16% 이하였다.
패턴을 읽을 필요조차 없다 — 시계만 보면 된다.

처음에는 패턴을 고쳐서 이 봇을 죽이려 했다. **세 번 실패했다**(42% → 9% → 2% → 6%).
정답은 죽는데 게임도 같이 죽었다. 이 게임은 10만 → 500억을 103판에 만들어야 해서
판당 기댓값 1.13 언저리가 생사선이고, 거기서 조금만 깎이면 클리어율이 절벽으로 떨어진다.

`DIP`를 같이 돌려보고 알았다:

| | 트레일12 (처음부터 보기) | 버티35 (4~5초 버티기) | 격차 |
|---|---|---|---|
| DIP 0.84 | 4% | 38% | 18%p |
| DIP 0.88 | 51% | 50% | 2%p |

시초 눌림이 0.84까지 파이면 3배 기준 **시작하자마자 −48%**라, 손절선을 건 사람은
진짜 상승 판에서도 매번 잘렸다. 그래서 "버티기"는 공짜 요령이 아니라 **유일하게
살아남는 법**이었다. 0.88이면 −36%라 손절선 안에서 버틸 수 있고, 그 순간
버티기의 값어치가 사라진다.

**확정안** — `DIP` 0.84 → 0.88 · `spike` .10 → .07(지분을 `earlypop`으로) ·
`earlypop`(초반 급등급락, 보통 .03) · `crash`(나락, 약세 .04) ·
하락 반등을 셋으로(없음 30% / 본전 못 넘음 35% / 1.00~1.14까지 35%).

| | 전 | 후 |
|---|---|---|
| 클리어 최고 · 격차 | 36% · 17%p | **26% · 6%p** |
| 판당 기댓값 트레일12 vs 버티35 | +0.318 | **−0.062** |
| 약세 판이 반등 없이 죽는 비율 | 15% | **79%** |
| 3초 안에 청산 | 0% | **8%** |
| 파산률(버티35) | 16% | **30%** |

**난이도 단계표(`TIERS`)는 안 건드렸다.** 3단계를 0.07로 올리는 쪽이 숫자는
깔끔했지만 그러면 3단계가 4·5단계보다 어려워져 사다리가 뒤집히고, 화면의
"하락 패턴 +N%p" 다섯 줄이 같이 바뀐다. 난이도는 나락과 반등실패가 만든다 —
"파산이 가능해진 만큼 어려워졌다"가 상수 하나 조율보다 정직하다.

#### 하락의 반등을 셋으로 가른 이유

예전에는 반등이 하나뿐이었고 **반드시 본전 위까지** 올라왔다. 그래서 "빠지면
기다렸다가 반등에 턴다"가 언제나 맞았고, 손절만 걸면 파산이 수학적으로 불가능했다.
셋이 같은 머리로 열리므로, 조금 올라왔을 때 **지금 털지 본전까지 기다릴지**가
처음으로 판단이 된다. 제일 고약한 건 가운데다 — 탈출은 되는데 손해 확정이다.

#### 종목은 성격대로 (새 패턴도 `patW`를 탄다)

- **ETF**는 `crash:0, earlypop:0`. 설명이 "급변 없음"인데 막지 않으면 지수를
  따라가는 종목에서 되돌림 없는 폭락이 나온다. 새 패턴을 넣을 때 `patW`를 같이
  보지 않으면 종목의 정체성이 조용히 깨진다.
- **동전주**는 `crash:2, earlypop:2`. "급등 아니면 급락뿐"이 정체성이다.

#### 시뮬을 믿기 전에 시뮬을 의심할 것 (이번에 세 번 당했다)

1. **`down`의 눌림 깊이를 시뮬에 `0.82`로 박아뒀다.** `DIP`를 올리자 강세만
   얕아지고 약세는 그대로라, 전반부 저점으로 등급이 읽히게 됐다 — `8a0acc7`이
   고쳐둔 것을 되돌리는 것이다. 같은 값이 두 시뮬 파일에 따로 박혀 있었다.
2. **"반등 없이 죽음"이 언제나 0%로 나왔다.** 최고가를 `1`에서 시작하는데 경로도
   `1`에서 출발하니 영영 0.97을 넘어 있다. 아무것도 안 재고 있었다.
3. **"반등 없음"이 0%로 나왔다.** 골짜기를 *지나는 지점*부터 최고가를 재서,
   반등이 아예 없는 판도 그 지점 값(≈0.95)이 최고로 잡혔다. 골짜기 *바닥*부터
   재야 한다.

그래서 `sim/confirm.js`는 이제 후보를 베끼지 않고 `_game.js`가 `index.html`에서
끌어온 **진짜 생성기**를 잰다. 베낄 수 없으면 어긋날 수도 없다.

#### 남은 숙제 둘 (이번 작업이 만든 것이 아니다)

- **쫄보·홀드가 0%다.** 고치기 전에도 0%였다. 살아 있는 전략이 트레일링 계열뿐이다.
- **동전주 85% · ETF 0%.** `⚠️` 절의 종목 균형 문제 그대로다. 조금 나아졌지만
  `patW`와 진폭을 따로 손봐야 하고, 이번에 같이 건드리면 무엇이 뭘 바꿨는지 알 수 없다.

### 「평가 계좌」 — 스토리를 한국어판에 되돌리기

**합의된 설정은 프랍 회사 평가다.** 근거는 `demo/artdir.html` 안 1("회사가 지원자에게
좋은 장비를 줄 리 없다")이고, 98 방향을 고른 이유 자체가 이거였다. 문안은
`demo/dialogs.html`에 한국어·영어로 **완성돼 있었다**(커밋 `4715bc7`).

그런데 게임에는 영어판만 들어가 있었다. i18n ④ 때 영어를 평가 계좌로 **새로 썼고**
(번역이 아니라), 한국어는 옛 빚 갚기 버전으로 남았다 — 창 제목은 `평가계좌_01.trd`인데
안에서는 대출금을 갚고 있었다. **같은 게임에 이야기가 둘 돌아갔다.**

| | 고치기 전 (ko) | 영어판 (이미 이랬다) | 지금 (ko) |
|---|---|---|---|
| 인트로 | 이 돈, 빌린 돈이에요 | This capital is not yours | 이 자금은 당신 돈이 아닙니다 |
| 실패 | 반대매매 | Account breached | 계좌 회수 |
| 완주 | 대출 완제 | Evaluation cleared | 평가 통과 |
| 정산 | 은퇴하고 새 인생 | Take the payout | 평가를 마치고 정산 |
| Lv.4 | 결혼 | Desk seat | 데스크 자리 |
| Lv.8 | 갚을 빚이 없어요 | You trade your own capital now | 자기 자본 |

**리스크 관리팀은 게임에 아예 없었다.** 파일 전체에서 "리스크" 0건이었는데,
이 문서가 *"반복되는 실패가 서사를 갉아먹는 대신 서사를 완성하는 유일한 장치"*라고
적어둔 게 그 줄이다. 차수 통과·계좌 회수·파산 세 모달에 붙였고 양쪽 언어 다 있다.
차수가 오를수록 말이 짧아지고, 회수에는 언제나 같은 한 줄이 온다.

- **말투는 합쇼체다.** 회사가 말하는 곳만이 아니라 한국어판 전체다. 회사는 화내지
  않는다 — 사무적일수록 무섭고, 그 톤이 설정의 일부다. 해요체 31개를 옮겼다.
- **댓글(`CHAT`)은 안 건드린다.** 회사가 아니라 다른 개미들이 쓰는 글이다.
  거기까지 합쇼체로 만들면 유일하게 사람 목소리가 나는 자리가 죽는다.
- **차수(1차~6차)는 그대로 뒀다.** 승인 문안은 "1단계"인데 게임은 난이도를 이미
  단계로 쓴다(1~5단계). 채용 평가의 1차·2차로 읽혀서 오히려 설정에 맞는다.
- **회사 이름은 메리디안**, 제품 이름은 머니로드. 제목표의 98 관용구는
  "문서 — 프로그램"이고 거기 오는 건 제품 이름이다. 회사는 인트로에서 한 번 댄다.
- **도장 아이콘 문제가 덤으로 풀렸다.** `✓ 해금됨` → `승인됨`이 되면서 ✓가 빠지고,
  도장이 "회사가 찍어준 것"이라는 제 뜻을 갖는다. 탭 이름도 해금 → 권한.

#### 서브셋 폰트를 다시 박는 법이 바뀌었다

문자열을 고치면 서브셋을 다시 돌려야 하는데, `__FONT_R__` 같은 자리는 첫 실행에
사라진다. 그래서 그동안은 돌릴 때마다 base64를 손으로 지워 자리를 되살려 놓고
실행했다 — 잊으면 조용히 옛 글리프로 남는다.

이제 `@font-face`마다 이름표가 박혀 있고(`/*@font:FONT_R*/`), `subset-font.py`가
자리가 없으면 이름표 뒤의 base64를 갈아끼운다. 같은 명령을 몇 번이고 다시 돌릴 수 있다.

```bash
python3 tools/subset-font.py index.html \
  FONT_R=<Pretendard-Regular.otf> FONT_B=<Pretendard-Bold.otf> \
  G11R=<Galmuri11.woff2>          G11B=<Galmuri11-Bold.woff2>
```

`EXTRA`에서 매도 등급 문구도 뺐다. 사전에 리터럴로 있으니 여분으로 들고 있을 이유가
없고, **적어두면 문구를 고쳐도 옛 글자가 계속 딸려 들어온다**(실제로 말투를 바꾼
뒤에도 "잘팔았어요"의 글리프가 남아 있었다).

### 데스크 — 창 안쪽을 책상 위 서류로 (1단계: 바탕)

98 회색은 **물러나라고 만든 언어**다(1998년 설계 목표가 그거였다). 버튼이 전부
`#c0c0c0` 하나고 글자는 검정 하나라, "무엇을 먼저 봐야 하는가"를 색으로 말할 수가 없다.
차트 패널만 읽히던 이유가 그거였다 — 거기만 값 대비가 있었다.

터미널 전면도 답이 아니었다. 대비는 생기지만 **위계가 없다** — 전부 얇은 선에 같은
색이라 한 덩어리로 보인다. 게임 UI가 읽히는 건 색이 아니라 **채워진 면 · 크기 점프 ·
기능별 색** 셋이다.

그래서 **창틀은 98, 안쪽은 책상**으로 간다. 제목표·메뉴바·상태표시줄·대화상자는
회색 그대로고(회사가 띄우는 창이니까), 플레이어가 읽는 면은 종이가 된다.
「평가 계좌」 설정과도 맞는다 — 회사가 주는 건 서류지 네온이 아니다.

**단계로 나눠서 넣는다.** 1단계는 CSS만이고 마크업·JS를 한 줄도 안 건드린다:

| | 전 | 후 |
|---|---|---|
| `.body` | 회색 | 책상 나무결 |
| `.grp` · `.tabpane` | groove 테두리 | 종이 한 장 (섬유결 + 책상 그림자) |
| `.main-tab` | 98 탭 | 서류철 탭 |
| 베팅 컨트롤 | 98 베벨 버튼 | 종이 칩 · 고르면 잉크로 채운다 |
| 금액 | 파인 입력창 | 밑줄 그은 기입란 |
| `.signal` | 흰 카드 | 담당자 소견 메모 (왼쪽 굵은 괘선) |
| `.trade-go` | 98 기본 버튼 | 도장 (이중 테두리 · 누르면 내려앉는다) |
| `.sell-btn` | 98 기본 버튼 | 책상 위 물리 버튼 (빨강 · 4px 그림자) |

**시작과 매도를 다른 물건으로 갈랐다.** 시작은 종이에 찍는 도장이고 매도는 책상 위
버튼이다. 판단하는 곳과 지켜보는 곳이 다른 물건이라는 것이 이 방향의 뼈대다 —
15초 동안 손이 가는 자리는 종이가 아니어야 한다.

**크기 체계를 벗어나지 말 것.** 서류 라벨에 11.5px을 들여왔다가 phase32에 바로
잡혔다(허용 12/12.5/15/17/19/26/40). 새 디자인을 넣을 때 제일 쉽게 새는 자리다.

#### 2단계 — 종목이 뭐가 다른지 한눈에

처음 계획은 종목을 **한 줄 칩**으로 눕히는 것이었다. 틀렸다 — 종목 차이를 말하는 것은
사실상 **미니 차트 모양**이고(ETF는 평평, 동전주는 톱니, 코인은 극단) 눕히면 그게 죽는다.
390px에서 여섯을 한 줄에 넣으면 "코스피E…"로 잘리고 26px 차트는 안 읽힌다.

**터치 규격이 값을 정했다.** 세로 목록은 한 칸 48px을 지키면 여섯 줄에 288px이 필요하다.
2×3 타일이면 절반인데, 그 절반을 아끼면 막대가 흩어져서 애초에 막대를 넣은 이유가 사라진다.

| | 높이 | |
|---|---|---|
| 지금 (차트+이름+설명) | 236px | 기준 |
| 한 줄 6칸 | 140px | 이름이 잘리고 차트가 안 읽힌다 |
| 장부 표 | 260px | 정확하지만 행이 48px 미만 |
| 타일 안에 선 + 막대 | 213px | 낮지만 막대가 흩어져 비교가 흐려진다 |
| **세로 목록 (선 + 이름 + 막대)** | **약 380px** | 채택 |

**높이를 주고 비교를 샀다.** 타일로 흩어 놓으면 막대의 출발점이 제각각이라 눈이
길이를 재야 한다. 세로 목록은 **여섯이 같은 왼쪽 눈금에서 출발**하므로 ETF가 진입선
옆 한 점이고 코인이 줄을 거의 다 쓴다는 것이 한 번에 보인다. 대신 한 칸 48px(터치
규격)을 지켜야 해서 격자보다 170px쯤 높다.

그 값을 치를 수 있는 이유는 **주문표가 스크롤해도 되는 화면**이기 때문이다.
스크롤이 절대 안 되는 건 라운드뿐이다 — 15초 동안 차트와 매도 버튼이 같이 보여야 한다.
두 화면의 제약이 다르다는 것을 한동안 섞어서 보고 있었다.

넣은 것 셋:

- **잉크 스파크라인** — 16×16 픽셀 비트맵을 종이에 그은 선으로. 흰 상자와 검은 외곽선이
  종이 위에서 혼자 놀았다. (도감 안내문은 아직 대화상자라 그쪽은 픽셀 아이콘 그대로다.)
- **범위 막대** — 진한 막대가 보통 범위, 옅은 막대가 극단, 빨간 선이 진입가(1.00x).
  눈금은 **로그**다. 선형으로 하면 ETF(0.81~1.26)가 점 하나로 뭉개진다.
- **눈금 한 줄** — 막대가 무엇인지 한 번은 말해야 한다(`0.05x — 1.00x 진입 — 3.5x`).
  로그 눈금이라 **가운데가 1.00x가 아니다**.
- **고른 종목 한 줄** — 게임이 이미 갖고 있는 설명(`ds`)만. 라운드 길이는 여섯 중 다섯이
  15초라 정보가 아니고(코인만 20초인데 그건 `ds`가 말한다), 범위 숫자는 막대가 이미 말한다.

**막대 값은 손으로 정한 게 아니다.** `sim/_game.js`의 진짜 생성기로 종목마다 6000판씩
재서 `TRADE_STOCKS[].rng`에 적었다. ⚠️ **패턴이나 진폭을 고치면 다시 재야 한다** —
안 그러면 막대가 거짓말을 한다.

**span에는 width가 안 먹는다.** 범위 막대를 `<span>`으로 만들었더니 폭이 0으로 눌렸다.
세로 목록 안에서는 플렉스 자식이라 저절로 블록처럼 굴어서, **같은 규칙이 자리에 따라
다르게 보였다** — 두 번 헛짚었다. `display:block`을 꼭 준다. phase32가 이제 막대 폭이
0인지 재서 잡는다.

#### 2단계-b — 단타 탭을 주문표 한 장으로

여섯 개의 그룹 상자가 각자 종이 한 장이었다. 종이 여섯 장이 겹쳐 있으면 서류가 아니라
카드 더미다. `.trade-panel`이 **종이 한 장**이 되고, 안쪽 `.grp`는 그 위의 **칸**이 된다
— 테두리·그림자·결무늬를 걷고 점선 한 줄로만 끊는다.

| | 전 | 후 |
|---|---|---|
| 패널 | 그룹 상자 여섯 장 | 종이 한 장 + 점선으로 끊긴 칸 |
| 머리 | 없음 | `주 문 표` · `No. 0142` (밑줄 2px) |
| 칸 순서 | 소견 → 종목 → 베팅금 → 조건 | 종목 → 베팅금 → 조건 → **소견** |
| 시작 | `50만원 × 3배로 시작` 버튼 | **승 인** 도장 + 금액 한 줄 |

**소견을 도장 바로 위로 내렸다.** 예전에는 장세 소견이 맨 위에 있어서 베팅금을 정하기
전에 읽고 잊어버렸다. 서류는 읽고 결재하는 순서로 읽히는 물건이라, 소견 → 도장이
붙어 있어야 그 순서가 생긴다.

**버튼이 동사에서 결재란이 됐다.** `…로 시작`은 문장이고 `승 인`은 도장이다. 금액은
도장 아래 작은 줄로 남는다 — 무엇을 승인하는지는 위 칸들이 이미 말했다. phase31이
보던 `/로 시작$/` 규칙이 이 자리에서 바뀌었고, 쓰이지 않게 된 `goStart` 문자열은 지웠다.

**절대배치한 라벨은 걸칠 테두리가 있을 때만 맞다.** `.grp > .lg`는 98 그룹박스의
테두리에 걸터앉으라고 `position:absolute`다. 테두리를 걷은 주문표 안에서는 그게
첫 줄을 덮는다 — 종목 목록 첫 칸이 `종목` 라벨을 먹었다. 주문표 안에서만 흐름에 되돌린다.

#### 3단계 — 라운드를 기기 안으로 (M1)

**판단하는 곳과 지켜보는 곳이 다른 물건이어야 한다.** 주문표는 종이고, 15초 동안
눈이 붙어 있는 차트는 **책상 위 기기(MERIDIAN · MT-14)**다. 껍데기만 새로 만들었다 —
퍼티색 몸통, 둥근 유리 모서리, 주사선, 반사, 아래턱 명판과 전원 LED.
`.trm`에서 뺀 것은 **자기 테두리와 그림자 한 줄뿐**이다(기기 안에서는 화면이 곧 유리라서).
차트 코드는 한 줄도 안 건드렸다.

**진짜 고친 것은 껍데기가 아니라 자리다.** 라운드 뷰는 `#tradeBody`, 그러니까
**주문표 안**에 들어가 있었다. 그래서 판이 도는 동안에도 주문표 머리와 종목 여섯 줄이
위에 그대로 남아, 차트가 접힘선 아래로 밀려났다 — 15초짜리 게임에서 차트를 보려면
스크롤을 해야 했다. 이제 `#roundHost`가 `#tabsWrap`과 형제로 서고, 판이 돌면
서류철이 통째로 접히고 모니터가 화면을 차지한다.

| | 전 | 후 |
|---|---|---|
| 라운드 뷰 자리 | `#tradeBody` (주문표 안) | `#roundHost` (서류철 밖) |
| 판이 도는 동안 | 탭 + 주문표 머리 + 종목 여섯 줄이 위에 | 전부 접힌다 |
| ACCOUNT 패널 | 156px 판때기 그대로 | 창틀의 계좌줄 44px로 접힌다 |
| 물타기 | 98 회색 상자 | 책상 위 버튼 |

**ACCOUNT 패널을 지우지 않고 접었다.** 목표와 D-day는 15초 동안에도 "언제 팔까"를
고르는 값이라 없애면 안 되는데, 156px짜리 판때기를 둘 자리는 없었다. 이미 스크롤용으로
만들어 둔 **접힌 계좌줄**(`.acct-mini`, 44px)이 창틀에 붙어 있으니 라운드 동안 그걸
강제로 띄운다 — 새 장치가 아니라 있는 것을 쓴다.

**라운드는 스크롤이 절대 안 되는 유일한 화면이다**(주문표는 스크롤해도 된다).
그래서 넘침을 실측해서 맞췄다:

| 화면 | 전 (주문표 안) | 후 | 해금 전부 켜고 |
|---|---|---|---|
| 390×844 | 넘침 | −274px | −181px |
| 360×640 | 넘침 | −70px | −23px |
| 320×568 | 넘침 | −41px | **+49px (알려진 한계)** |

짧은 화면(`max-height:640px`)에서는 **껍데기 여백만** 줄인다 — 차트는 지금 그대로
가기로 한 자리다. ⚠️ **미디어 쿼리는 특정도를 안 올려준다** — `.trm .round-mult`를
`@media` 안에서 33px로 내렸는데 아래에 있는 44px 규칙이 계속 이겼다. 미디어 블록을
그 규칙들 **뒤로** 옮겨야 먹는다. 그리고 터미널 안 크기는 **11의 배수**여야 한다
(Galmuri11이 11px 격자다 — phase32가 본다). 44 → 33이 그래서 나온 값이다.

**남은 한계:** 320×568에 메타 해금을 전부 켜면(물타기 줄 + 절반 매도) 49px이 넘친다.
차트(150px)를 건드리지 않고는 더 못 줄인다. 실기준선은 360×640으로 잡았다.

#### 4단계 — 나머지 서류 (체결 통지 · 권한 대장 · 비품 신청서 · 계좌 회수)

단타 탭만 서류가 되고 나머지는 98 흰 리스트박스로 남아 있었다. **탭은 화면이 아니라
서류 종류다** — 펼친 서류마다 제 이름을 이고 있어야 그 말이 값을 한다.

| 탭·화면 | 전 | 후 |
|---|---|---|
| 단타 | 주 문 표 | (3단계에서 끝남) |
| 상점 | 흰 리스트 + 98 버튼 | **비 품 신 청 서** · 장부 행 · 「신 청」 도장 |
| 권한 | 흰 리스트 + 픽셀 도장 아이콘 | **권 한 대 장** · 승인란이 오른쪽 세로줄 |
| 결과 팝업 | 회색 대화상자 | **체 결 통 지** · 「체결」 도장 · 「다 음 판」 |
| 기한 초과 · 파산 | 회색 대화상자 + 경고 아이콘 | **계 좌 회 수** · 「회수」 도장 |

**창틀은 회색으로 남는다.** 바뀐 것은 대화상자 안에 든 종이뿐이다 — 회사가 띄우는
창은 회사 것이고, 그 창이 내미는 서류가 종이다. `.dlg`에 `doc` 클래스가 붙는 대화상자만
종이가 되고, 인트로·정산·난이도 같은 안내는 회색 그대로다. ⚠️ **클래스는 열 때마다
정해야 한다** — `.dlg`는 하나뿐이라 지우지 않으면 다음 대화상자가 앞 대화상자의 얼굴을
물려받는다. 그래서 `$('modal').classList.add('on')` 열한 군데를 `openModal(kind)` 하나로 모았다.

**승인·체결·회수가 같은 양식이다.** 실패가 특별한 사건이 아니라 **절차**로 읽혀야 한다 —
그게 이 게임의 주제다. 그래서 기한 초과 화면에서 경고 아이콘을 뺐다. 회사는 화내지 않는다.

**도장은 띄워서(`float`) 찍는다.** 처음에는 절대배치로 얹었는데 문서마다 줄 높이가
달라서 어떤 화면에서는 금액 옆 빈자리에, 어떤 화면에서는 글자 위에 앉았다(「등급이
없습니다」가 도장 밑에 깔렸다). 띄우면 뒤따르는 줄들이 알아서 도장을 피해 흐른다 —

**말도 같이 바꿨다.** 상점의 「강화」가 「신 청」이 됐다 — 평가 계좌 설정에서 플레이어는

### 창을 창으로 만들기 (모바일 상단 고정)

"스크롤을 내려도 잔고·D-day가 남아야 한다"는 요청을 **새 장치를 다는 일이 아니라
창을 창으로 만드는 일**로 풀었다. 98 창은 원래 제목표·메뉴바·상태표시줄이 틀이고
구르는 것은 클라이언트 영역뿐이다.

```
#app  { height:100dvh; overflow:hidden; }   /* 창틀 */
.body { flex:1 1 auto; overflow-y:auto; min-height:0; }   /* 클라이언트 영역 */
```

이러면 상태표시줄(연승·오늘 판수)도 덤으로 바닥에 붙는다. 예전에는 문서 맨 아래라
한 번도 안 보이던 줄이다. `dvh`를 쓰는 이유는 주소창이 접히고 펴지는 만큼
`100vh`가 거짓말을 하기 때문이다.

**실제로 당한 것 둘:**

1. **ACCOUNT 패널이 높이 0으로 접혔다.** `.body`가 스크롤 통이 되는 순간 자식들은
   기본 `flex-shrink:1`로 줄어드는데, `#repayGrp`은 `.trm`이라 `overflow:hidden`이
   걸려 있어서 안쪽이 넘쳐도 항의를 안 한다. 그대로 0까지 눌린다.
   → `.body > *{flex-shrink:0}`. 스크롤 통 안에서는 아무도 안 줄어들어야 한다.

2. **주석에 쓴 한글도 서브셋 검사에 걸린다.** "튕"을 주석에 한 번 썼다가
   `check.sh`의 폰트 가드가 잡았다. 파일 전체를 훑으므로 코드와 주석을 못 가른다.
   낱말을 바꾸는 쪽이 가드를 무르게 만드는 것보다 싸다 — **쓰는 낱말이 곧 폰트 용량**이다.

**접힌 계좌줄**(`.acct-mini`)은 창틀에 붙어 있어서 `sticky`가 필요 없다.
본문 스크롤이 40px을 넘으면 뜬다(0으로 두면 고무줄 스크롤에서 깜빡인다).
잔고·목표·D-day 셋만 둔다 — 판당 필요 수익률은 ACCOUNT 패널과 시작 버튼 위
페이스 경고가 이미 두 번 말한다. 값은 패널 DOM을 긁지 않고 상태에서 직접 읽는다.

고정 영역은 152px(제목표 32 · 메뉴바 51 · 계좌줄 35 · 상태표시줄 34).

### 메타 해금 사다리의 순서 원칙

먼저 오는 해금은 **지금 하는 일을 더 깊게** 만들고, 새 축을 여는 것은 읽는 법을
배운 뒤에 온다.

공매도가 첫 칸(40 XP ≈ 두 판)에 있었다. 값어치가 **약세 등급을 읽는 데서** 나오는
기능인데 패턴 도감보다 여섯 칸 먼저 열려서, 읽는 법을 배우기 전에 방향 선택지만
두 배가 됐다. 네 번째(400 XP)로 옮기고 분할 매도를 첫 칸으로 당겼다 — 매도 타이밍이
이 게임의 전부인데 그걸 반으로 쪼개게 해주는 쪽이 첫 보상으로 맞다.

| | 전 | 후 |
|---|---|---|
| 40 | 공매도 | **분할 매도** |
| 140 | 분할 매도 | **물타기** |
| 260 | 물타기 | **코스피ETF** |
| 400 | 코스피ETF | **공매도** |
| 560~900 | 동전주 · 도감 · 코인 | 그대로 |

**문턱 값은 안 건드렸다.** 옮기는 것은 순서지 속도가 아니다 — 같이 만지면 무엇이
난이도를 바꿨는지 알 수 없게 된다. 기존 세이브는 XP가 그대로라 같은 칸 수만큼
열려 있지만 **무엇이 열렸는지는 달라진다**(300 XP: 예전 공매도·분할·물타기 →
지금 분할·물타기·ETF).

테스트의 씨앗 XP도 같이 움직인다. `phase21`은 `SHORT_XP` 상수 한 줄로 모았다 —
다섯 군데에 200이 흩어져 있어서 다음에 옮길 때 하나를 빠뜨리게 돼 있었다.

### 상표·저작권 규칙 (98 방향을 고른 뒤의 전제)

UI 관용구(3D 베벨·타이틀바·메뉴바·상태바)는 기능적 표현이라 문제가 없다. 위험한 건 **에셋과 상표**다.

1. 제품 어디에도 **"Windows"를 쓰지 않는다**(스토어 설명 포함). `retro desktop OS`로 쓴다.
2. **로고·깃발·시작 버튼·작업 표시줄을 만들지 않는다.** 응용 프로그램 창 하나만 쓴다.
3. **아이콘은 전부 직접 그린다.** MS 시스템 아이콘을 참고하지 않는다.
4. **서체는 OFL만** — MS Sans Serif·Tahoma·Segoe UI 임베드 금지.
5. **소리도 직접 만든다.** 시동음·오류음 샘플 금지.
6. BSOD 패러디를 쓰더라도 **문구는 새로 쓴다.** 클리피 유사 캐릭터도 금지.

`demo/win.html` — **윈도우 UI × 픽셀, 4세대(98 / XP / 10 / 11).** 안 1과 맞물리는 방향이다 —
회사가 지원자에게 좋은 장비를 줄 리 없으니, 낡은 업무용 PC의 창 하나가 곧 세계관 설명이 된다.
타이틀바·메뉴바·상태바·그룹박스·모달 대화상자가 전부 **게임에 그대로 쓸 수 있는 장치**다
(단계 통과·계좌 회수는 대화상자, D-day는 상태바, 리스크 매니저 메시지는 트레이 알림,
15초는 진행 막대).

98은 3D 베벨(`border-color:#dfdfdf #000 #000 #dfdfdf` + inset 1px 이중 베벨)로 눌림을
반전 표현할 수 있어 촉감이 가장 좋고, XP는 밝아서 장시간 반복에 눈이 편하다.
10은 현행과 가장 가깝고, 11은 둥근 모서리·부드러운 그림자가 픽셀과 정면으로 충돌한다.
레트로 OS는 마우스용이라 버튼이 원래 23px인데, **비율만 지키고 크기는 48px 이상으로 키웠다.**

### charset 함정

파일 앞부분이 base64 폰트로 가득 차면 브라우저가 첫 1KB에서 UTF-8을 감지하지 못하고
windows-1252로 떨어져 **한글이 통째로 깨진다.** 폰트를 박는 문서에는
`<meta charset="utf-8">`을 첫 줄에 둔다.

`demo/pixelfix.html` — **픽셀 렌더 확정 + 터치 규격.** `ux.html`이 "픽셀로 안 보인다"는
지적을 받고 원인을 찾은 문서다. 셋이었다:

1. **`-webkit-font-smoothing:none` 누락.** 픽셀 폰트는 이게 없으면 브라우저가 계단을
   문질러서 그냥 좁은 고딕이 된다. `pixelround.html`에는 있는데 `ux.html`에서 빠졌다.
2. **설계 그리드에서 어긋난 크기.** Silkscreen은 8px 격자인데 11px로 썼다 —
   1.375배 리샘플링이라 계단이 어긋난다. 8/16/24/32만 쓴다.
3. **CDN 의존.** Google Fonts 링크 하나에 기대면 네트워크·CSP 중 무엇에 막혀도
   **조용히 기본 고딕으로 떨어진다**(오류도 안 난다). 이제 woff2를 파일에 박는다.
   `@fontsource/*`를 npm 레지스트리에서 받는다 — jsDelivr는 이 환경에서 막힌다.

**서체 결론:** 본문 **Pixelify Sans 16px** + 배율·주 버튼만 **Press Start 2P**.
읽는 글자와 소리치는 글자를 갈랐다. Silkscreen은 16px에서 상단 타이머가 잘리고
8px은 너무 작아 이 UI에 안 맞는다. 실측은 문서의 폰트 비교 칸에 있다.

**터치 규격:** 최소 48×48px(Material 48dp·Apple 44pt 중 큰 쪽), 인접 간격 10px,
매도 88px·시작 72px, 위험 버튼(매도/물타기)은 16px 떼어놓기, 라운드 중 매도 외 비활성.
6칸 종목 격자는 48px로 키우면 메인이 스크롤되므로 **전체 화면 시트로 분리**했다.

> `ux.html`(31~40)은 **조작 모델 비교용 문서로 남긴다.** 거기에 진짜 픽셀 폰트를
> 넣어보면 38곳이 잘린다 — 11px 조밀 레이아웃이 픽셀 폰트 폭을 못 버틴다는 뜻이고,
> 그게 `pixelfix.html`에서 글자를 키우고 컨트롤 수를 줄인 이유다.

### CSS 특정도 함정 (세 번 당했다)

`.scr button{...}`은 **(0,1,1)**이라 `.p-cta`(0,1,0)를 **이긴다.** reset에
`background`·`color`·`font-size`·`text-align`을 두면 주 버튼의 배경이 사라지고
글자색이 뒤집히고 정렬이 왼쪽으로 간다 — 전부 실제로 겪었다.
**reset에는 어떤 버튼 규칙과도 충돌하지 않는 속성만 둔다**(`font-family:inherit`,
`border:0`, `cursor`). 한 글자 클래스(`.g`)도 쓰지 말 것 — 유틸 클래스와 토큰이 겹친다.

`demo/ux.html` — **4차 · UX 10안(31~40).** 아트 디렉션이 **23 CRT ARCADE로 확정**된 뒤의
문서다. 남색 CRT 팔레트 · Silkscreen · 2px 프레임 · 옅은 주사선 · 글자에 글로우 없음,
그리고 **차트는 픽셀화하지 않는다** — 매끈한 선에 면채움, 끝점에 현재가 점.

이 대비가 컨셉이다: **UI는 픽셀**(회사가 준 낡은 기계), **데이터는 매끈**(시장은 진짜다).
픽셀이 장식이 아니라 화자가 된다.

그래서 이 페이지의 변수는 하나뿐이다 — **조작 모델**:
31 BASELINE(현행) · 32 THUMB ZONE(조작을 하단 40%로) · 33 ON-CHART(익절선을 차트 위에
드래그 — 삭제했던 자동 익절의 부활안) · 34 ZEN(라운드 중 배율·차트·매도만) ·
35 PRO(세로 지표 레일로 전부 노출) · 36 CONFIRM(진입 전 요약 시트) ·
37 RING TIMER(남은 시간이 테두리) · 38 INLINE RESULT(결과 모달을 차트 위 겹침으로) ·
39 DECK(종목을 카드로 넘김) · 40 HOLD TO SELL(길게 눌러 매도).

안마다 **맞교환**을 같이 적었다 — 이 문서의 목적은 고르는 것이지 구경이 아니다.
번호는 조합해서 지정할 수 있다(예: `32 + 34 + 38`).

**주의 — 루트 클래스는 `.scr`다.** 처음에 `.g`로 썼다가 내부 유틸 클래스 `g`(초록)와
같은 토큰이라 `<b class="g">`가 아트보드 규칙(max-width·flex·min-height 548px)을
통째로 받았다. 한 글자 클래스는 쓰지 말 것.

`demo/artdir3.html` — **아트 디렉션 3차(21~30) · 픽셀 농도.** 조건이 셋으로 좁혀진 뒤의 안이다 —
차트는 반드시 유지(라운드 화면 높이의 35~45%), 픽셀은 과하지 않아도 됨, 레트로~현대.
그래서 레이아웃을 왕도로 고정하고 **"픽셀을 어디에 얼마나 넣는가"만** 변수로 뒀다.
비교할 변수가 픽셀의 정도라면 나머지를 고정해야 그게 보인다.

농도 1~5를 각 안에 표기한다: 1=차트만 · 2=차트+작은 라벨 · 3=차트+서체 전반 ·
4=위 + 테두리·그림자 · 5=전부(색 수까지 제한).

`chart(mode, opts)`가 일곱 가지를 그린다 — `dot`(액정 점격자) · `dither`(1비트 체크무늬
면채움) · `step`(계단) · `pixcandle`(격자에 스냅한 캔들) · `blocks`(8비트 기둥) ·
`line`(매끈한 선) · `neonstep`(계단+글로우). 픽셀 모드는 전부 `shape-rendering="crispEdges"`에
좌표를 `px` 격자로 스냅한다. **차트 렌더는 UI와 독립이라 조합이 가능하다** —
"UI는 26인데 차트는 22처럼" 같은 지시가 그대로 먹는다.

배경과 글자는 항상 다른 명도대, 본문 환산 11px 이상.

게임 상태는 1차와 같은 값을 쓴다(PHASE 3 · $34,800 · D-7 · NOVA 3배 $24,000 · 1.18배).
`candleSVG()`가 PATH를 3틱씩 묶어 16봉으로 만들고, 우측 가격축·거래량·진입선을 같이 그린다 —
16·18번이 이걸 쓴다.

`demo/artdir.html` — 해외판 아트 디렉션 10종 비교. 메인·라운드 두 화면을 10벌씩 그려
20장을 한 페이지에 깐다. **20장 전부 같은 게임 상태**(PHASE 3 · 잔고 $34,800 · D-7 ·
NOVA 3배 $24,000 · 1.18배)를 그리므로 차이는 오직 디자인에서만 온다. 문구는 해외판
설정인 「평가 계좌」(프랍 회사 평가) 기준 영어고, 금액은 $1,000 시작 → $500M 완제로

게임 `<style>`을 복사해 쓰는 다른 목업들과 달리 이건 **새 디자인 제안**이라 스타일을
공유하지 않는다. 대신 화면 구성(종목 6칸·신호 행·레버리지 3단·퀵 4개·페이스 경고 등)은

버리면 Galmuri 서브셋 파이프라인이 통째로 필요 없어지고, Artifact CSP도
fonts.googleapis.com은 허용하므로 Pages판과 Artifact판 서체가 처음으로 같아진다.

`demo/pixelround.html` — 라운드 화면 픽셀아트 버전. 게임의 경로 생성기와 손익 공식을

`demo/redesign.html` — 메타 해금 9종·난이도 선택·정산 화면을 세로 블록 증가 없이

다시 복사해야 화면이 거짓말을 안 한다.** 모달 계열(`.emo`/`.tt`/`.dc`/`.ok`)만

## 🛠 앱 안 테스트 도구

상단 로고(**머니로드**)를 **1.5초 안에 2번** 누르면 열린다. 평소 화면에는 흔적이 없고
모달 하나만 쓴다. 라운드 중에는 안 열린다 — 15초짜리 판 위에 모달이 뜨면 그 판을 잃는다.
2번 탭은 브라우저 더블탭 확대와 겹치므로 `.brand`에 `touch-action: manipulation`을 걸어뒀다.

다섯 탭이다. "이 값을 만지려면 어느 탭인가"가 바로 떠오르게 갈랐다.

**탭은 "무엇을 만지는가"로 갈랐다.** 상태(지금 XP가 몇인가)는 🎬 시작이고,
밸런스(XP가 얼마나 빨리 자라는가)는 🧬 메타다.

| 탭 | 무엇 |
|---|---|
| 📊 패턴 | 10종의 **실제 경로 3개**·등급·가중치 ±·등장 확률·패턴별 초반↑. 행을 누르면 다음 판 강제 |
| 🧬 메타 | **XP 공식 계수** · 조기 상환 XP · 난이도 XP 배수 · 파산 XP 페널티 · **해금 문턱 7개** |
| 🎬 시작 | XP · 해금 칩 · 난이도 1~5 · 시작 현금 · 최소/최대 레버리지 · 상환 단계 · 거래일 |
| 💸 파산 | **파산선 · 청산 여유(`LIQ_K`) · 기한 연장 일수/비용** + 즉시 파산·반대매매·정산 화면 |
| ⚖️ 밸런스 | `MID_DIP` · `DIP` · 신호 적중률 · 조기 상환 보너스 |

메타 탭의 해금 문턱 오른쪽에는 **"몇 판 만에 열리나"**가 파랗게 붙는다
(3단계에서 1억까지 가는 판을 한 판으로 친다). 문턱을 만지면 같이 움직여서
숫자를 외우지 않고 "코인이 9판째"를 바로 본다.

`LIQ_K`는 **1.00이 원금 전액 손실선**이다(롱 `1−K/L`, 숏 `1+K/L`). 내리면 전액을
잃기 전에 잘린다 — `sim/deadends.js`가 0.55~0.85를 훑어본 그 축이고,
난이도가 가장 세게 움직인다.

값마다 **무엇이고 어느 쪽이 어려워지는지**를 옆에 적어 둔다(`.dv-help`).
어려워지는 방향: MID_DIP ↑ · DIP ↓ · 적중률 ↓ · 보너스 ↓ · 파산선 ↑ · 청산 여유 ↓

헤더 우측에 📋 템플릿과 🧹 전부 초기화가 어느 탭에서든 붙어 있다.
탭 바닥에는 `↺ 이 탭 기본값`과 `▶ 재시작`이 있다 — **↺는 그 탭 값만** 되돌리고,
시작 현금·레버리지는 새 판이라야 듣기 때문에 ▶가 탭 안에 있어야 한다.

### 📋 템플릿 — 작업 고리

앱에서 값을 맞추고 JSON을 넘기면 그대로 코드에 박는다. 이게 이 도구를 만든 이유다.

1. 앱에서 값을 만진다 → 2. ▶ 재시작으로 몇 판 굴린다 → 3. 마음에 들면 슬롯에 저장
→ 4. 📋에서 `전체 선택` 후 길게 눌러 복사해 넘긴다 → 5. 코드에 박고 시뮬로 재본 뒤 배포

```json
{"v":2,"패턴":{"up":0.22,"down":0.22,"v":0.12,"spike":0.1,"flat":0.08,
 "invv":0.1,"w":0.1,"m":0.1,"delayup":0.04,"delaydown":0.04},
 "MID_DIP":1,"DIP":0.84,"신호적중률":0.55,"조기상환":0.1,
 "레버리지":{"최소":3,"최대":3},"시작현금":100000,"거래일":[13,13,13,15,15,17,17],
 "메타":{"XP계수":20,"조기상환XP":2,"난이도배수":1,"파산페널티":0.3,
  "해금문턱":[40,140,260,400,560,740,900]},
 "파산":{"파산선":10000,"청산여유":1,"연장일수":3,"연장비용":0.25}}
```

- **설정만 담는다.** 측정값(초반↑ 같은 것)은 안 담는다 — 받아서 직접 다시 재는 쪽이 안전하다.
- `불러오기`는 붙여넣기라 **양방향**이다. "이 값 한번 써보세요" 하고 JSON을 드릴 수 있다.
- 슬롯 3칸은 `moneyroad2_devtpl_v1`에 따로 저장되고 **전부 초기화에서 빠진다**
  (`devWipe`가 `devtpl`이 든 키를 건너뛴다). 맞춰둔 값을 잃으면 그 시간이 통째로 날아간다.
- 복사는 클립보드 API 대신 전체 선택으로 간다 — 모바일에서 권한이 막히는 경우가 있다.

**밸런스 값·패턴 강제는 저장하지 않는다** — 새로고침하면 돌아온다(슬롯만 남는다).
XP를 임의로 넣어 기록이 오염되면 메타 탭의 "메타만 초기화"로 되돌린다.

### 체결 통지를 리스크 관리팀이 읽는다 (커뮤니티 댓글 삭제)

체결 통지는 **회사가 발행한 문서**인데 거기에 「개미핥기 · 깔끔하게 먹었네요 · 공감 65」가
붙어 있었다. 사내 문서에 바깥 목소리가 섞여 있던 셈이다. 리스크 관리팀이 읽는 쪽으로
바꾸고 `CHAT{ko,en}` 블록(작성자 이름 30개 · 반응 5등급 · 사건 10종 × 2언어)을 통째로 지웠다.

**무작위로 고르지 않는다.** 리스크 관리팀은 즉흥으로 말하지 않으므로 조건이 맞는
첫 줄을 쓴다 — 같은 판에는 같은 말이 나온다(phase31이 스무 번 읽어서 확인한다).
최대 두 줄: **매도 등급 한 줄 + 상황 한 줄**(연승·대박·연속 끊김·마지막 날).
청산은 등급을 말하지 않는다 — 판단이 아니라 사고다.

칭찬의 최대치가 **「기록해 두겠습니다」**다. 위로도 하지 않는다 —
청산에는 「배율은 회사가 정하지 않았습니다」가 온다.

같이 지운 것: `buildReactions` · `EVENT_LINES` · `nameFor` · `FAKE_NAMES` · 대박/참사 배지
(`rsHot`/`rsCold` — 커뮤니티가 떠드는 크기를 재던 값이다) · `.cm-feed`/`.cm-msg`/`.rs-like`.
⚠️ **죽은 한국어 문장은 폰트 용량이다** — 서브셋이 파일 전체를 훑으므로, 안 쓰는 문자열을
남겨두면 그 글리프가 계속 실려 나간다.

### 주문표 5단계 — 종목과 베팅금을 한 화면에 (N4 → 2열 격자)

세로 목록(N4)을 고른 이유는 **「여섯 막대가 같은 왼쪽 눈금에서 출발해야 길이 비교가
된다」**였고, 그 값으로 높이 170px을 치렀다. 실제로 돌려 보니 그 값이 너무 비쌌다:

| | 전 | 후 |
|---|---|---|
| 종목 목록 | 303px | **177px** |
| 종목 맨 위 → 베팅금 맨 아래 | 513px | **364px** (쓸 수 있는 자리 494px) |
| 본문 총높이 (390×844) | 1186px | 979px |
| 접힘선 아래 | 463px | 256px |

**막대를 버리고 작은 그래프를 넣으니 격자로 가도 잃는 것이 없다.** 예전에는
성격(선 모양)과 크기(막대 길이)를 **두 개의 마크로 나눠** 그렸고, 막대는 왼쪽 눈금을
공유해야만 읽혔다. 하나로 합치면 그 제약이 사라진다 — **선 모양이 성격을, 세로 진폭이
크기를** 말하고, 진폭은 손으로 정한 값이 아니라 실측 범위(`rng`)에서 나온다
(`instAmp()`가 로그 눈금 폭을 0~1로 접는다: ETF 0.23 · 사성전자 0.33 · 동전주 0.63 ·
코인 1.00). 칸 가운데 점선이 진입가(1.00x)라 칸마다 같은 기준선을 갖는다.

눈금 줄(`0.05x — 1.00x 진입 — 3.5x`)은 **가로 막대를 설명하던 것**이라 같이 지웠다.
그래프에서는 가로가 시간축이므로 그대로 두면 거짓말이 된다.

**잠긴 종목 라벨이 반대로 읽히고 있었다.** `instLockMeta:'해금'` — 잠긴 줄에 「해금」이
적혀 있으니 *해금됐다*는 뜻으로 읽힌다(영어판은 `Locked`로 맞았다). 메타 해금이라
「등급 Lv.4 / Lv.6 / Lv.8」로 적는다. 「등급」을 붙이는 이유는 네코프로의 `Lv.3`이
**판 안의 레벨**이고 이쪽은 **트레이더 등급**이라 다른 사다리이기 때문이고,
권한 대장이 쓰는 말(등급·승인)과도 같아진다.

**도장이 「승 인」에서 「매 수」가 됐다.** 서류 말투로는 승인이 맞지만 버튼이 실제로
하는 일은 매수다 — 아래 라운드 화면의 「전량 매도」와 짝이 된다.

**결재란.** 도장이 128px밖에 안 되고 옆의 두 줄짜리 문구가 나머지 폭을 다 먹고 있었다.
그 문구는 매 판 똑같고 상단 D-day가 이미 같은 말을 한다 — 읽히지도 않으면서 화면에서
제일 중요한 버튼을 반으로 줄이고 있었다. **도장을 폭 전체로** 키우고 문구는 아래 한
줄로 내려 첫 3판에만 보인다. 도장 안 작은 줄에 **고른 종목 이름**을 같이 적는다
(`5만원 × 3배 · 사성전자`) — 목록을 다시 안 봐도 무엇을 사는지 보인다.

**하단 대기 모니터 삭제.** 판이 없을 때도 「다음 판 대기」 줄이 82px을 먹고 있었는데
아무 값도 주지 않았다. 모니터는 판이 돌 때만 나온다.

### 종목 밸런스 — 재던 자가 틀려 있었다

**시뮬이 게임이 아니라 사본을 재고 있었다.** `sim/_game.js`는 "베끼지 않고 원본에서
잘라온다"는 게 존재 이유인데, **종목 표(`G.STOCKS`)만 예외로 손으로 옮겨 적혀 있었다.**
그 사본이 조용히 어긋나 있었다 — 동전주 `patW`는 게임과 아예 다른 값이었고
(`spike` 3 vs 2.5 · `up` 0.4 vs 1.0 · …), ETF는 나중에 들어온 `crash`·`earlypop`을
안 막고 있었다. 이제 `TRADE_STOCKS`를 통째로 잘라서 평가한다(UI 필드는 전부 게터라
배열을 만드는 시점에는 `t()`도 `ic()`도 안 불린다).

**전략 봇도 종목 길이를 몰랐다.** 「25%를 버틴다」가 `Math.floor(T*0.25)`로 T=300에
고정돼 있어서, 400틱(20초)짜리 코인에서만 26%·18%를 버티는 다른 전략을 재고 있었다.
경로 길이에서 뽑게 고쳤다.

둘을 고치니 그림이 뒤집혔다 — **코인은 고장난 적이 없었다(13% → 52%).**

| 종목 | 해금 | 전 (사본) | 후 (실측) | 최고 전략 | 기댓값 | 청산 |
|---|---|---|---|---|---|---|
| 사성전자 | 시작 | 39% | 27% | 트레일12 | 1.59 | 0% |
| 네코프로 | 판 Lv.3 | — | 30% | 버티35 | 1.78 | 14% |
| 유메이드 | 판 Lv.5 | — | 50% | 버티35 | 2.17 | 19% |
| 코스피ETF | 등급 Lv.4 | 4% | **6% → 28%** | 버티25 | 1.51 | 3% |
| 동전주 | 등급 Lv.6 | 98% | 70% | 버티35 | 2.19 | 11% |
| 코인 | 등급 Lv.8 | 2% | **52%** | 버티35 | 2.43 | 23% |

**진짜 문제는 ETF 하나였다.** 첫 종목 해금(등급 Lv.4)인데 이미 갖고 있는
사성전자(26%)보다 한참 나빴다 — **보상이 함정이었다.** 원인은 단순하다: 급변 패턴을
전부 막아 상방만 걷어내고 하방은 그대로 뒀다. 위험도 없고 갈 곳도 없는 종목이 된다.

고친 방향은 **진폭이 아니라 등급 안 분포**다 — "급변 없음"이 이 종목의 정체성이라
`pMult`/`noiseMult`는 손대지 않았다. 완만한 하락을 0.6으로 누르고 상승 1.2·횡보 1.15로
올린다(`patW`). 등급 분포는 강세 20→25% · 약세 36→28%로만 움직여서 신호는 그대로
쓸모가 있고, "지수는 개별 악재가 없어서 약세 판이 덜 나온다"가 그대로 말이 된다.

**동전주 70%는 안 건드렸다.** 등급 Lv.6 해금이고 코인(Lv.8, 52%)과 같은 대역이다.
사다리가 올라가면서 쉬워지는 것은 로그라이크의 리듬이고, 그 값을 받는 자리는
난이도 단계(1~5)지 종목이 아니다.

**막대 값도 다시 쟀다.** `TRADE_STOCKS[].rng`는 사본으로 잰 값이었다 — README가
경고해 둔 바로 그 상황이다("막대가 거짓말을 한다"). `sim/range.js`로 정의를 못 박고
다시 쟀다: **보통 = 그 판에서 도달한 최저·최고의 25~75 백분위, 극단 = 10~90.**
결과가 훨씬 잘 갈린다 — ETF는 짧은 토막, 유메이드·코인은 눈금을 거의 다 쓴다.

새 시뮬 셋:

- `sim/inst.js` — 여섯 종목 × 여섯 전략 전수. "이 종목이 세다"와 "이 종목엔 저 전략이
  맞다"를 갈라서 본다. 종목마다 최고 전략이 다르면 그건 밸런스가 아니라 성격이다.
- `sim/instfix.js` — 한 종목의 손잡이(pMult·noiseMult·patW) 후보 스윕.
- `sim/range.js` — 막대 값 실측. ⚠️ 패턴·진폭·patW를 고치면 반드시 다시 돌린다.

## ⚠️ 보통 등급 4종을 고친 뒤 (미해결)

초반 25%에 +5% 이상 오르는 판이 **37%**였다. 원인은 보통 등급 넷 —
눌림목·급등급락·고점후하락·이중고점이 전부 오르며 열렸다. 패턴 개편 때
`up`/`down`만 고치고 보통 4종을 손대지 않은 탓이다.

넷 다 `midHead()`로 열게 바꿨다. 판마다 확률로 눌리며 열거나 오르며 연다.
`MID_DIP`이 그 확률의 배수다.

**밸런스는 아직 안 맞는다.** 초반 상승은 37%→13%로 내려갔지만 클리어율이
같이 무너졌다(사성전자 트레일링 6%→1~2%). 보통 등급이 수익 구간을 대부분
공급하고 있었기 때문이다. 손으로 두 번 조정해봤지만(고점 시점 ±) 안 돌아왔다.

그래서 손잡이를 도구에 냈다. `MID_DIP`과 패턴 가중치를 실제로 플레이하면서
맞추는 쪽이 시뮬로 더듬는 것보다 빠르다. **기본값 1.0은 임시값이다.**
